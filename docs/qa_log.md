## Q-001: このリポジトリを作った経緯（2026-10-24）

- **相談**: プロジェクトごとに安全ルールやドキュメントの雛形を作るのは手間。同じようなテンプレートはないか。
- **回答/検討**:
  - 部分的なものはあった（Anthropic 公式の devcontainer、Trail of Bits の推奨設定、git の誤操作を止める skill など）。ただ、ドキュメント一式と安全設定をまとめたものは見つからなかった。
  - そこで、最初のプロジェクトで作った設定を、自分用のテンプレートにすることにした。
- **決定**:
  - GitHub のリポジトリ `claude-project-template` に置く。GitHub のブランチ保護を使うため Public にする。
  - Trail of Bits の設定と git-guardrails のルールを取り込む。
  - `~/.claude` に入れる前に、入れる内容をすべてドキュメントにしてユーザーが確認する。シェルスクリプト（install.sh）は使わない。
  - 個々の決定は [design.md](design.md) の 4 章。

## Q-002: 判断事項への回答（2026-10-24）

- **決定**:
  - 権限チェックを飛ばすモードは使用禁止。
  - main への直接の push はやめる。develop を作って保護し、作業ブランチから develop への PR で取り込む。PR のマージはユーザーが行う。
  - シェル設定の編集は拒否。
  - Trail of Bits の、利用状況の送信を止める設定は入れる。
  - 会話の履歴は約半年（180 日）残す。
  - `rm -rf` はすべて止める。trash も禁止。消すときはフォルダ単位などで確認してから消す（ファイルは Claude が 1 つずつ確認して消し、フォルダはユーザーが消す）。

## Q-004: GitHub への登録（2026-10-24）

- **相談**: このリポジトリを GitHub に登録したい。コミットのメールアドレスは Gmail でよいか。ダミーでもよいか。
- **回答/検討**:
  - Public リポジトリでは、コミットの作者のメールアドレスを誰でも読める。収集されてスパムの原因になり、一度 push すると消すには履歴の書き換えが要る。
  - ダミーのアドレスでも動くが、GitHub がコミットをアカウントに結びつけない（アイコン・草が付かない）。
  - GitHub の noreply アドレスなら、アドレスを隠したままアカウントに結びつく。
- **決定**:
  - `kip2/claude-project-template` を Public で作る。
  - コミットのメールアドレスは、このリポジトリだけ GitHub の noreply アドレスに設定する。
  - 最初の push は、設計どおりユーザーが `--no-verify` で行う。
